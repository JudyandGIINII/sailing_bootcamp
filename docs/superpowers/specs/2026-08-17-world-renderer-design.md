# World renderer — design

> 상태: **설계 승인됨 (구현 전)**
> 작성일: `2026-08-17 KST`
> 대상 PRD 절: §6.1 (drift trail을 보여주는 HUD), FR-04
> 경계: 렌더러는 합성·미검증 값만 그린다. 실제 해도·항법·안전 표시가 아니다.

## 1. 문제

시뮬레이션은 동작하지만 화면에서 아무것도 움직이지 않는다.

`src/render/world-projection.ts`는 41줄짜리 장식용 스텁이다. 캔버스에 어두운 사각형과
정적인 물결, 고정 좌표 `(248, 74)`의 흰 막대를 그리고, `render()`에서 갱신하는 것은
helm 색과 텍스트 두 줄뿐이다. **`position_m`, `heading_rad`, drift를 하나도 읽지 않는다.**

그 결과 보트가 600 m 북쪽 마크까지 200틱 넘게 항해하는 동안 화면은 정지해 있고, 숫자만
바뀐다. PRD §6.1이 MVP 포함 항목으로 명시한 **drift trail**은 어디에도 없다.

데이터는 전부 준비되어 있다. ledger가 매 틱 위치를 기록하므로(확인:
`polar_transition.next_state.position_m`) **새 상태 없이 렌더러만의 작업**이다.

## 2. 확정된 설계 결정

| ID | 결정 | 근거 |
|---|---|---|
| D-1 | **보트 추적 시점** — 보트를 화면 중앙에 고정하고 세계를 스크롤 | 사용자 선택. 조타 반응과 근처 궤적이 크게 보인다 |
| D-2 | 마크가 화면 밖일 때 **가장자리 인디케이터 + 거리**를 표시 | D-1의 약점(마크가 안 보여 "얼마나 빗나갔는지" 판단 불가) 보완 |
| D-3 | 궤적은 **ledger에서 유도**하고 새 상태를 만들지 않는다 | 이미 매 틱 위치가 있다. 상태를 늘리면 픽스처·replay 계약이 다시 흔들린다 |
| D-4 | 투영 수학과 세션 유도를 **순수 모듈로 분리**, PixiJS는 얇은 어댑터 | Pixi 렌더는 단위 테스트가 어렵다. 계산을 분리하면 실제로 검증할 수 있다 |
| D-5 | heading과 COG를 **함께 그린다** | 두 방향의 각도 차이가 L04의 학습 신호 자체다 |

### 기각한 대안

- **전체 코스 고정 시점** — 마크·궤적·보트를 항상 함께 보여 표류 판단에 직결되지만
  사용자가 추적 시점을 선택했다.
- **내용에 맞춘 자동 확대·축소** — 척도가 계속 변해 표류량을 눈으로 비교하기 어렵다.
- **궤적을 세션 상태에 저장** — ledger로 충분하고, 상태 추가는 골든 픽스처와 replay
  identity를 다시 건드린다.

## 3. 모듈 구성

기존 패턴(순수 모듈 + 얇은 어댑터)을 따른다.

| 파일 | 책임 | 순수성 |
|---|---|---|
| `src/render/camera.ts` (신규) | 세계 좌표 → 화면 좌표 투영, 화면 밖 판정, 가장자리 인디케이터 위치·각도 | 순수 |
| `src/render/session-view.ts` (신규) | 세션에서 보트 상태·궤적·마크를 유도 | 순수 |
| `src/render/world-projection.ts` (재작성) | PixiJS 드로잉 어댑터 | Pixi 의존 |

`src/render`는 `tests/contracts/sim-boundary.test.ts`의 스캔 대상이 **아니다**(스캔 범위는
`src/sim`). 그래도 `camera.ts`와 `session-view.ts`는 순수하게 유지한다 — 시계·난수·DOM·
네트워크를 쓰지 않는다.

## 4. 좌표 규약

`docs/contracts/coordinate-contract.md`가 이미 고정한다: `+x = east`, `+y = north`,
각도는 north 기준 시계방향 라디안.

화면은 y가 **아래로** 증가하므로 투영에서 y를 뒤집는다:

```
screen.x = width/2  + (world.x - centre.x) / metres_per_pixel
screen.y = height/2 - (world.y - centre.y) / metres_per_pixel
```

## 5. 뷰포트

- 캔버스 `520 × 360` px
- `metres_per_pixel = 0.6` → 가시 범위 약 `312 × 216 m`

마크 W1은 (0, 600), 시작 위치는 (12, −8)이므로 **처음부터 마크가 화면 밖**이다. 가장자리
인디케이터(D-2)가 첫 프레임부터 동작한다.

## 6. 그리는 것

| 요소 | 내용 |
|---|---|
| 물 | 배경 |
| 궤적 | 지나온 위치를 이은 폴리라인 (drift trail, PRD §6.1) |
| 보트 | `heading_rad`로 회전한 글리프. 실제 10 m는 몇 px이라 과장해 그린다 |
| COG 광선 | 보트에서 `cog_rad` 방향으로 뻗는 짧은 선. heading과의 각도 차이가 표류다 |
| 마크 | 화면 안이면 원 + 도달 반경(25 m) 원. 화면 밖이면 가장자리 삼각형 + 거리(m) |
| 수심 여유 | `clearance_level`에 따른 테두리 색 (clear/caution/danger) |

### 접근성

캔버스는 현재 `aria-hidden="true"`다. 이를 유지하되, 캔버스가 전달하는 정보를 **텍스트
대체**로 함께 제공한다(마크까지 거리·방위, 표류각, 여유 상태). 색만으로 상태를 구분하지
않는다 — 저장소의 기존 원칙이다.
